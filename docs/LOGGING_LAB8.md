
# ЛР №8 — Структурированное логирование FishTrack

## Назначение

FishTrack использует структурированные JSON-журналы для диагностики HTTP-запросов, ошибок и инцидентов.

Журналы выводятся в stdout контейнеров приложения и доступны через Docker logs.

## Поля журнала

- timestamp — время события в UTC
- level — уровень INFO, WARNING или ERROR
- event — тип события
- method — HTTP-метод
- path — шаблон HTTP-маршрута
- status_code — HTTP-код ответа
- result — результат операции
- duration_ms — длительность выполнения в миллисекундах
- request_id — уникальный идентификатор запроса
- instance_id — экземпляр app1 или app2
- exception_type — тип исключения без его содержимого

## Безопасность

В структурированные журналы запрещено записывать:

- пароли;
- токены авторизации;
- cookies и значения сессий;
- заголовки Authorization;
- тела HTTP-запросов;
- query-параметры;
- строки подключения к базе;
- сообщения исключений с конфиденциальными данными.

Uvicorn access logs отключены.

Nginx access logs отключены.

## Просмотр журналов

Экземпляр app1:

    sudo docker logs fishtrack-demo-app1-1 --tail 50

Экземпляр app2:

    sudo docker logs fishtrack-demo-app2-1 --tail 50

## Диагностика

Каждому HTTP-запросу присваивается request_id.

Он возвращается пользователю в заголовке X-Request-ID и сохраняется в журнале.

Заголовок X-Instance-ID показывает обработавший запрос экземпляр.

## Проверки

- make lint
- make sast
- make test
- make verify

Тестирование выполняется исключительно с отдельной тестовой БД.

## Действия при утечке секрета

1. Ограничить доступ к затронутым журналам.
2. Отозвать или заменить скомпрометированный секрет.
3. Исправить источник небезопасного логирования.
4. Добавить регрессионный тест.
5. Подтвердить отсутствие повторной утечки.
