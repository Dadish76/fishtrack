## 2. Методика

Исходный снимок сохранен перед обновлением. В локальном окружении пересозданы только `app1` и `app2`, выполнена проверка и перезагрузка конфигурации Nginx. PostgreSQL, сеть приложения и контейнеры мониторинга сохранены. Для AFTER выполнен Smoke Test и 60 последовательных GET-запросов к `/api/v1/trips` с паузой 200 мс между запросами; все ответы HTTP 200. Перед нагрузкой выдержано пятиминутное окно после старта новой версии. После нагрузки выдержана пауза для сбора метрик. Отдельный вывод о 60 запросах BEFORE не представлен, поэтому сравнение не считается строгим экспериментом при идентичной нагрузке.

Данные получены из Prometheus. Скорости запросов, ошибок, задержки и CPU рассчитаны по окну `[5m]`; доступность, готовность, RAM и счетчики рейсов — моментальные значения. Скриншоты Grafana показывают последние 15 минут и могут включать оба состояния и переход между ними.

Относительные изменения рассчитаны как `(AFTER − BEFORE) / BEFORE × 100%` по исходным неокругленным значениям. Для CPU и RAM указана разница в процентных пунктах. Нулевая скорость HTTP 5xx (выражение с `or vector(0)`) интерпретируется совместно с доступностью и успешными HTTP-проверками, а не как самостоятельная гарантия отсутствия ошибок. Счетчик рейсов является счетчиком событий в процессе, может сбрасываться при перезапуске и не отражает число записей в PostgreSQL. CPU и RAM относятся к Linux-среде Docker Desktop, не ко всему Windows-компьютеру.

## 5. Наблюдения по графикам

На графиках Grafana AFTER (15 минут) видны кратковременные пики CPU экземпляров около 6–6,5% одного ядра и p95 HTTP около 0,85–0,9 с вблизи времени обновления. Показатель p95 на этой панели относится к ее собственному набору маршрутов и интервалу расчета, поэтому не равен пятиминутному p95 конкретного GET `/api/v1/trips` в таблице. Причина пика по одному графику не установлена. График RAM экземпляров временно показывает около 140–145 МиБ на ряд с последующим возвращением к 60–80 МиБ. В переходный период возможны одновременно старые и новые временные ряды cAdvisor; требуется проверка по идентификаторам контейнеров, чтобы установить причину. Устойчивого роста этих показателей на представленном интервале не наблюдается. Не следует утверждать, что выпуск прошел без какой-либо кратковременной деградации или что во всем интервале отсутствовали ошибки.

## 6. Источники и воспроизводимость

Первичные JSON-снимки сохранены в каталоге `$HOME/fishtrack-lab8-evidence` вне репозитория: `before-release.json` и `after-release.json`. Дополнительные доказательства: вывод PowerShell с локальным выпуском, Smoke Test, контрольной нагрузкой, скриншоты Grafana и Prometheus Alerts до и после выпуска.

Основные PromQL-выражения:

```promql
up{job="fishtrack"}
fishtrack_app_healthy{job="fishtrack"}
sum(rate(fishtrack_http_requests_total{job="fishtrack",path="/api/v1/trips",method="GET"}[5m]))
sum(rate(fishtrack_http_errors_total{job="fishtrack",status=~"5.."}[5m])) or vector(0)
1000 * sum(rate(fishtrack_http_request_duration_seconds_sum{job="fishtrack",path="/api/v1/trips",method="GET"}[5m])) / sum(rate(fishtrack_http_request_duration_seconds_count{job="fishtrack",path="/api/v1/trips",method="GET"}[5m]))
1000 * histogram_quantile(0.95, sum by (le) (rate(fishtrack_http_request_duration_seconds_bucket{job="fishtrack",path="/api/v1/trips",method="GET"}[5m])))
100 * (1 - avg(rate(node_cpu_seconds_total{job="node",mode="idle"}[5m])))
100 * (1 - node_memory_MemAvailable_bytes{job="node"} / node_memory_MemTotal_bytes{job="node"})
fishtrack_trips_created_total{job="fishtrack"}
```

Состояния пяти правил получены через `/api/v1/rules`; версия и готовность — через `/version` и `/health` на локальном порту 18080.

## 7. Вывод

Состояние системы до и после локального выпуска зафиксировано и сравнено. На момент AFTER оба экземпляра доступны и готовы, PostgreSQL подключена, контрольные запросы и Smoke Test успешны, правила Prometheus неактивны. Существенного ухудшения показателей в двух контрольных снимках не обнаружено. Кратковременные пики в интервале обновления отмечены отдельно; причинно-следственные выводы о производительности по двум снимкам не делаются. Проверка выпуска на собственной staging-ВМ остается открытой.
